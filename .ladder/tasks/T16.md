- /register: non-JSON body or bad client metadata (e.g. lone surrogate in client_name) → 400 `invalid_client_metadata`, no traceback.

- Keep every other test green; no real hostnames.

## Result
Files changed: src/skein/oauth.py, src/skein/service.py (`is_loopback` only), tests/test_oauth.py.

- Basic client auth (T15 #1) and revoke (#2): `_ClientAuthForm`, an ASGI shim inside the body cap, in front of the SDK token and revoke handlers. It parses form-encoded bodies with Starlette, as the SDK does. With a valid Basic header and no `client_id` in the form, it adds the header's id, and its secret if the form has none. A different form id gets 401 `invalid_client` with `WWW-Authenticate: Basic` and no-store. On /revoke it adds an empty `client_secret` when the form has none. The secret check stays in `HashedSecretAuthenticator`, so a client that holds a secret still needs it (401).
- Consent hand-back (#4): approve and deny return a 200 page with no-store, `<meta http-equiv="refresh" content="0;url=…">` and a Continue link, both HTML-escaped. There is no 303. The CSP on every consent page is exactly C8. `frame-ancestors`/`base-uri` were dropped and the redirect origin is no longer listed. `X-Frame-Options: DENY` still blocks framing. `_csp_source` was removed.
- /register (#5): `_RegisterBody` sends back 400 `invalid_client_metadata` for a body that is not JSON, is not a JSON object, is nested too deep to parse, or has a lone surrogate in any key or value. There is no traceback and no row is stored.
- Loopback (#6): a requested URI with a fragment or userinfo no longer matches. `is_loopback` strips `[ ]`, so `[::1]` on any port works.

Acceptance: `uv run pytest -q` → `364 passed, 1 warning in 5.14s` (pass).

Open issues:
- Only `application/x-www-form-urlencoded` bodies are rewritten. A multipart token request with Basic and no client_id still gets 401, as before. The `Basic` scheme is matched case-sensitively, as the SDK does.
- Still not checked in a real browser: does Chrome follow the meta refresh to the app, and to a private-use scheme? Do this during the redeploy check.
- Not in scope, still open: the /register response has no `Cache-Control: no-store`.

## Review (round 1)
Verdict: approve

Every item in the brief is done, with a test for each, and I found no security problem.

Checked: `git diff 4e8b38c -- src/skein/oauth.py src/skein/service.py tests/test_oauth.py`; PLAN.md C8 and the ledger decision on the hand-back; the SDK's `ClientAuthenticator`, `RevocationHandler` and `RequestBodyLimitMiddleware` in `.venv`. Acceptance `uv run pytest -q`: `364 passed` (load average 4.1). `ruff check` on the three files passes. I also ran throwaway probes from outside the repo against the test app. Nothing in the repo was changed except this file.

Against the brief:
- Basic client auth: `_ClientAuthForm` wraps the SDK handlers and sits inside the body cap. Code exchange and refresh with Basic and no body `client_id` return 200, for both a registered and a CLI-added client. Ids that differ get 401 `invalid_client` in both directions and the code is not spent. A wrong Basic secret gets 401. The secret check is still only in `HashedSecretAuthenticator`.
- /revoke: a public client with `token` + `client_id` gets 200 and both tokens stop working. A client that holds a secret gets 401 with no secret, an empty one, a wrong body secret or a wrong Basic secret, and its tokens stay valid. Basic with the right secret works.
- Hand-back: approve and deny return 200 with `no-store`, one meta refresh and a Continue link to the same escaped address, and no `Location`. The CSP is exactly the C8 text on every consent page. A hostile state and a redirect with `&` and `'` come out escaped and read back unchanged.
- /register: ten bad bodies (not JSON, cut short, not text, nested too deep, not an object, lone surrogates in values and keys) all get 400 `invalid_client_metadata`, no traceback, no row stored.
- Loopback: fragment and userinfo are refused, `[::1]` matches on any port, and a full sign-in on another port works for both 127.0.0.1 and `[::1]`.
- Hygiene: only `example.com` hostnames in the diff; no names, paths or addresses.

What the probes added (all fine):
- The 4 MB body cap still answers 413 on `/token` with the shim in place, with and without a Content-Length.
- A chunked body, a `charset` parameter on the content type, and non-UTF-8 bytes in other fields all survive the form rewrite.
- A public client cannot refresh or revoke another client's token through the Basic path. A wrong Basic secret is refused even when the body carries the right one.
- `/register` with `NaN`, `1e999`, an empty body, `null` and a UTF-16 body never returns 500.
- A redirect address is checked at registration against `javascript:`, `data:` and similar schemes, so the new Continue link cannot carry one; the CSP would block a script link anyway.

Not blocking, no change asked:
- src/skein/oauth.py:1078: `Headers(scope=scope)` is built before the `scope["type"]` check. A non-HTTP scope has no headers and would raise. The router only sends HTTP here, so it cannot happen today; swapping the two lines would make the class safe on its own.
- The real-browser check (does Chrome follow the meta refresh, also to an app scheme) is still open, as the result says. It belongs to the redeploy check and should happen before the user's retry.
- The three open issues in the result are accurate: multipart bodies and a lowercase `basic` scheme are not rewritten (I confirmed lowercase gets 401 `Missing client_id`, same as the SDK), and the `/register` response still has no `Cache-Control: no-store`.
