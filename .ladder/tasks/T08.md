# T08: Config — strict types per key + allowed_origins
Tier: haiku · Reviewer: sonnet · Deps: T07 findings

## Brief
Goal: a config value of the wrong type must fail loudly at load time, never silently change behaviour.
Contract: PLAN.md §C3 (plus the T08 decision line: new key `[server] allowed_origins = []`, Config field `allowed_origins: tuple[str, ...]`, default `()`).
Files: src/skein/config.py, skein.example.toml, tests/test_config.py
Acceptance: `uv run pytest tests/test_config.py -q`
Constraints:
- Check each key's type after reading TOML: host/base_path/db/audit_log/owner/answer_time → str; port → int (not bool) in 1..65535; url_tokens → bool only (the string "false" must raise); public_hosts and allowed_origins → list of str. Wrong type → ValueError naming the key.
- An explicit path (argument or SKEIN_CONFIG) that doesn't exist → FileNotFoundError; only the implicit ./skein.toml may be missing (then defaults).
- Reject base_path that starts with "//".
- Add allowed_origins to skein.example.toml with a comment: extra Origin header values the MCP endpoint accepts (needed only if a connector sends an Origin header and gets 403).
- Tests for every one of the above (url_tokens = "false" must raise is the key case).
