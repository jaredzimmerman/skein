### Issues, most severe first (all low, none blocking)
1. `src/skein/cli.py:145-153`: `main` catches `SkeinError` and `ValueError` only. A missing `--config` or `SKEIN_CONFIG` path now raises `FileNotFoundError`, so the user sees a Python traceback instead of `skein: config file not found: ...`. It does fail loudly and exits non-zero, so T07 item 9 holds; the message is just rough. T08 recorded this for T09 and it was missed. Fix: also catch `OSError` (covers an unreadable config too), plus one CLI test.
2. `agents/muse/README.md:12` (and `agents/_template/README.md:9`): the `url_tokens` fallback is suggested without the sentence the Claude README now has, that the reverse proxy's access log must be off or strip query strings. Both already say the token ends up in URLs and logs, and `deploy/nginx.conf.example:9-11` and `README.md:164` carry the warning, so nothing here is false. T07 item 2 named the Muse line and T11's review asked for it. For the deploy step: if any member uses `?token=`, turn the proxy's access log off or drop the query string first.
3. `README.md:139`, `docs/architecture.md:144`: "404 and 405 responses are not logged" is too broad. A request to an unknown route or with a wrong method is not audited, but a 404 from a real route (an unknown task or ask id) is; the smoke shows the `GET /tasks/{id}` 404 line. Say "requests to unknown routes or with a wrong method".
4. `src/skein/mcp_tools.py:112`: with the SDK logger at WARNING, a refused request prints `Invalid Origin header: <value>` or `Invalid Host header: <value>` to the server's stderr (seen in the smoke). The value is header text from an already signed-in caller and is never a token, but `README.md:142-143` says the audit log is the only record. Raise that logger's level or add one sentence to the README.
5. `docs/architecture.md:5,104`: links to `.ladder/PLAN.md` (T07 item 13). Fix together with the owner's `.ladder` decision.
6. `deploy/skein.service:31-33`: `UMask`, `StateDirectory` and `StateDirectoryMode` read correctly but were not validated; run `systemd-analyze verify` on the server before `enable --now`. Note the install comment's `sudo -u skein skein init` creates the database under sudo's umask (usually 0644); the 0700 directory still keeps it private.

Hygiene: the diff adds only `example.com` / `example.net` hosts, `127.0.0.1`, and made-up text. No real hosts, names, paths or tokens.

Safe-to-deploy note: yes, as it stands, with headers-only clients or with `url_tokens` on. With `url_tokens` on, the one remaining place a token can be written is the reverse proxy's own access log, which is the deployer's setting.
