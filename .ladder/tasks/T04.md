# T04: CLI + tests
Tier: haiku · Reviewer: sonnet · Deps: T01 (service), T02 (config)

## Brief
Goal: the `skein` command for the person who runs the server.
Contract: .ladder/PLAN.md §C6 (commands, behaviour), admin methods in §C2 as implemented in src/skein/service.py (read it; don't change it), config loader in src/skein/config.py.
Files: src/skein/cli.py, tests/test_cli.py
Acceptance: `uv run pytest tests/test_cli.py -q`
Constraints:
- argparse, stdlib only. `main(argv=None) -> int` so tests call it directly; `--config PATH` on the top-level parser. `serve` imports `skein.app` and `uvicorn` lazily inside the command (T03 is built in parallel; don't import them at module top).
- `member add` prints the token on its own line plus a one-line warning that it won't be shown again. `member list` and `status` print readable plain text (name, display, point marker, disabled, last seen).
- Any SkeinError → message on stderr, exit code 1.
- Tests (use tmp_path config with a temp db, capture stdout/stderr with capsys): init creates db; add prints a `skein_` token; duplicate add → exit 1; list; rotate gives a different token and the old one no longer authenticates; disable/enable; point set/show; point set to unknown member → exit 1; status output contains the point. Don't test `serve`.
