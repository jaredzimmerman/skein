### Issues, most severe first

Must fix before deploy:

1. **Public-repo hygiene, `.ladder/HANDOFF.md:7,9-11`, `.ladder/LEDGER.md:2,12,22`** (already pushed to the public origin). These tracked files contain absolute local paths with the macOS username and workspace ids, a note naming a second GitHub account and how the credential helper is set up, and notes about a private server and which assistants will join. PLAN's hygiene rule forbids personal details. Source, tests, agents, docs and deploy are clean (only `skein.example.com`, `127.0.0.1`, "Sam"). Needs an owner decision: scrub the lines going forward (they stay in history), or also rewrite history, which needs a force-push the standing rules forbid. Either way, stop logging `scriptPath=` and account notes into tracked files.
2. **Tokens reach the server's own log, `src/skein/cli.py:101`.** `uvicorn.run` keeps the default access log, which prints the full request line with its query string. In the smoke, `GET /api/whoami?token=<token>` put the token in the server log even with `url_tokens` off (the request was refused, the token was still logged). With `url_tokens = true`, the fallback `agents/claude/README.md:36` and `agents/muse/README.md:12` recommend, every request writes that member's token to journald under the shipped unit. `agents/claude/README.md:36` says skein never records it; only the audit log is clean. Fix: `access_log=False` (the audit log already covers requests) or strip the query string, plus a test.
3. **A security switch fails open, `src/skein/config.py:75-88`.** Values are not type-checked. `url_tokens = "false"` (a quoted string) loads as a truthy value and turns URL tokens on; I confirmed `?token=` is then accepted. `port = "8771"`, `host = 5` and `audit_log = 3` also load and fail later. Fix: check bool/int/str per key and raise `ValueError`, plus tests.

Should fix soon:

4. **State files are world-readable, `deploy/skein.service:5` and `:19-40`.** The database and audit log are created 0644 and the install line makes `/var/lib/skein` 0755, so any local user on a shared server can read every task, result and ask. Add `UMask=0077` to the unit and `-m 0700` to the state directory.
5. **Earlier results are lost on follow-up, `src/skein/service.py:359-362` and `:475`.** The "result amended" note is only added when the task is still final. After a point follow-up the task is queued, so the next submit overwrites the old result with no trace; the same happens to a `needs_input` question once the member re-submits. `docs/architecture.md:77-78` says each amendment keeps the previous result. Either keep a server note whenever a non-empty result is replaced, or correct the doc.
6. **Disabling the point leaves it as the point, `src/skein/service.py:581-586`.** Members can still file asks (200) that nobody can answer. `skein status` shows it, but `member disable` should warn or refuse while the member is the point.
7. **MCP Origin allow-list has no setting, `src/skein/mcp_tools.py:83-87`.** Any request carrying an `Origin` that isn't a `public_hosts` entry is refused with 403. If a vendor's connector sends its own Origin, every MCP call fails and nothing in the config can allow it. Check on the first real connect; add an `allowed_origins` key if needed (a ledger decision, since C3 is frozen).

Low:

8. `src/skein/service.py:48` — the member name `server` is allowed, and its notes are indistinguishable from the server's own `from: "server"` notes. Reserve the name.
9. `src/skein/config.py:101-102` — an explicit `--config` path that doesn't exist silently yields defaults (C3 says so, but for an explicit path it hides typos; the server then runs on an empty `./skein.db`).
10. `README.md:125`, `docs/architecture.md:37-38,124` — "every request" is audited is not accurate: MCP `initialize` and `tools/list`, the GET help page and 404/405 responses write no audit line. Only tool calls, REST calls and failed sign-ins do.
11. `src/skein/rest.py:54` — REST bodies have no size cap (the MCP path inherits the SDK's 4 MiB cap). Authenticated callers only; set `client_max_body_size` in the proxy or cap here.
12. `README.md:143`, `deploy/nginx.conf.example:23`, `deploy/Caddyfile.example:9` — these talk about MCP streams; the server answers with plain JSON and never streams. Harmless, slightly misleading.
13. `docs/architecture.md:5,99` — public docs point readers to `.ladder/PLAN.md` for the contracts; if issue 1 ends with `.ladder/` leaving the repo, these links break.
14. By contract, not a bug: after a point change the new point's inbox shows neither tasks still assigned to it nor its own unseen answers (it must use `skein_tasks` / `skein_get_ask`). Worth one line in `agents/*/point.md`.
15. Not re-verified by me: the claude.ai connector UI steps and plan limits in `agents/claude/README.md:22-32` and the scheduling limits in `agents/claude/scheduled-checkin.md:16-18` are marked as checked against vendor docs on 2026-11-10.

Safe-to-deploy note: with `url_tokens = false` and headers-only clients, the code as it stands is safe to run behind the example proxy. Issues 2 and 3 must be fixed before anyone turns `url_tokens` on; issue 1 is independent of the deploy and needs the owner.
