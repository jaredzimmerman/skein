## Brief
Goal: OAuth-only MCP clients can become a skein member; everything that works today keeps working.
Contract: PLAN.md §C8 (read it fully), plus §C1–C6 for the parts you touch. Existing code: src/skein/*.py.
Files: src/skein/oauth.py (new: provider, consent page, routes), src/skein/store.py (v2 tables + v1→v2 migration + oauth CRUD, still no rules), src/skein/service.py (rotate/disable revoke OAuth grants; oauth client admin functions), src/skein/config.py (+ keys, strict types, validation), src/skein/app.py and src/skein/auth.py (mount routes, accept access tokens, WWW-Authenticate resource_metadata), src/skein/cli.py (`oauth client add|list|remove`), skein.example.toml, tests/test_oauth.py (+ small additions to existing test files if needed).
Acceptance: `uv run pytest -q` (all green, old and new)
Constraints:
- Use the installed mcp 1.30 auth modules (`.venv/lib/python3.11/site-packages/mcp/server/auth/`). Read their source; don't guess signatures. If an SDK handler can't be mounted under base_path cleanly, wrap it, don't fork it.
- Tests (written first), all through the real ASGI app with httpx: metadata at root path-inserted and base-appended URLs with correct issuer/resource/endpoints; 401 carries resource_metadata when enabled and not when disabled; full flow with DCR client: register → authorize (S256) → consent GET shows client name → POST with wrong token (error, counted) → POST with member token → code → token exchange → MCP `skein_whoami` and REST `/api/whoami` return that member; refresh rotation (old refresh rejected); code reuse rejected; wrong PKCE verifier rejected; expired code/pending/access token rejected (injectable clock); redirect_uri mismatch rejected; CLI client with secret (wrong secret rejected) incl. trust-on-first-use redirect lock; `rotate_token` and disabling the member revoke its OAuth tokens; OAuth disabled → no oauth routes (404) and fixed tokens unaffected; two members via OAuth concurrently never see each other's identity; v1 database file (create with the pre-T13 schema) migrates and keeps members/tasks; audit/log output never contains tokens, secrets, codes or verifiers; consent page headers (CSP, X-Frame-Options, no-store) and HTML-escaped client name.
- No real hostnames (skein.example.com only).

## Result
Files changed: src/skein/oauth.py (new), src/skein/store.py, src/skein/service.py, src/skein/config.py, src/skein/app.py, src/skein/auth.py, src/skein/cli.py, skein.example.toml, tests/test_oauth.py (new, 76 tests), tests/test_service.py (schema version 1→2 assertion only).

Acceptance `uv run pytest -q`: PASS. Summary line: `322 passed, 1 warning in 5.19s` (the warning is Starlette's existing httpx/TestClient deprecation).

What was built (C8):
- Store schema v2 (oauth_clients, oauth_pending, oauth_codes, oauth_tokens), applied in place on open with the version re-read inside BEGIN IMMEDIATE. A v1 file built from the literal pre-T13 DDL migrates and keeps members, point, tasks and asks (tested).
- SDK pieces from mcp 1.30: AuthorizationHandler, TokenHandler, RegistrationHandler, RevocationHandler, build_metadata, the two metadata handlers, ClientAuthenticator, cors_middleware, RequestBodyLimitMiddleware. Mounted under base_path directly rather than through create_auth_routes, which mounts at root and compares plaintext client secrets. `HashedSecretAuthenticator` wraps the SDK authenticator without forking it: for one request, `get_client` returns the presented secret only when its hash matches.
- Metadata is served root path-inserted and base-appended (AS, openid-configuration, PRM). 401s carry `resource_metadata` only when OAuth is on. When OAuth is off there are no routes: 401 without a token, 404 with one.
- Consent: 10 min, 5 bad attempts, request ids random, pending capped at 200 (oldest dropped). Codes are hashed, single-use, 10 min, and bound to client, redirect_uri, PKCE, member and resource. A replayed code revokes its grant. Access and refresh tokens are hashed and bound to member, client and resource. Refresh rotates. Revoke ends the whole grant. Access tokens are accepted on the same middleware identity path. Disabled members are refused.
- `rotate_token` and disabling a member delete its codes and tokens. `skein oauth client add|list|remove` exists. The TOFU lock is applied at the first approved https redirect and re-checked inside the approval transaction.
- DCR is capped at 50; at the cap, idle registrations older than a day are pruned. Registration is limited to 10 per minute for the whole server (429 + Retry-After).
- Audit: register, consent_ok/failed/denied/conflict, token_issue/refresh/revoke, code_reuse, <route>_failed, register_limited. These records hold ids, member names, attempts and status only. Tested against every secret.

Deviations / open issues for review:
1. CSP `form-action` also lists the client's redirect origin, plus `frame-ancestors 'none'; base-uri 'none'`. Chrome applies form-action to the redirect after the POST, and with `'self'` alone the hand-back to the app would be blocked. Not verified in a real browser.
2. Scope leniency: the server always grants `skein`, whatever scope was requested (RFC 6749 §3.3). Registration accepts any requested scope and stores `skein`.
3. A CLI client with a secret accepts either client_secret_basic or client_secret_post. Loopback http redirect URIs match any port (RFC 8252 §7.3).
4. Config: when public_url is set, its path must equal base_path. Bad config raises ValueError. With base_path "" the issuer serializes as "https://host/" (pydantic AnyHttpUrl), matching the SDK.
5. Docs (README, architecture, proxy .well-known locations) are left for T14.

Verdict: changes

Issues (fix these):
1. src/skein/oauth.py:747 (`consent`, with `_decide` at :507): the member token is checked in one transaction (`skein.authenticate`, a read) and the code is issued in another (`_decide`, a write). A `rotate_token` or disable that commits between the two leaves a code, and then tokens, that outlive it. Reproduced: `authenticate(old token)` → `rotate_token("alpha")` → `_decide(req, "alpha")` → `/token` 200 and `/api/whoami` returns alpha, while the old fixed token is 401. Someone holding a leaked token can loop authorize + consent (neither is rate limited) to land in that window, and rotation is the remedy for a leaked token. → Resolve the token to a member inside `_decide`'s write transaction: pass the token (or its hash), look it up with `db.get_member_by_token_hash`, require enabled and `hashes_match`. Then a rotation or disable is either before (no code) or after (`delete_oauth_member` removes the code). Add a test that rotates between the check and the decision and asserts no code and no working token.
2. tests/test_oauth.py:791: `cursor://anysphere.cursor-retrieval/oauth/callback` is a real vendor's redirect address in a public repo (hygiene rule: example names only) → use a made-up private-use scheme such as `com.example.app:/oauth/callback`.

Verified good:
- Redirects: exact match (loopback http any port), never a redirect to an unregistered URI, fragments/javascript/data/file/plain http refused for both DCR and CLI clients, TOFU lock re-checked inside the approval transaction.
- PKCE: S256 only (plain and missing refused), wrong verifier refused, challenge shape checked.
- Codes: hashed, single use (marked inside the exchange transaction), 10 min, bound to client/redirect/challenge/member/resource; replay revokes the grant; another client can't redeem.
- Tokens: hashed, bound to member + client + resource, refresh rotates in one transaction, expiry on the injectable clock, revoke ends the grant, a foreign client's revoke does nothing, refresh tokens are not accepted as bearer and access tokens are not accepted as refresh or at consent.
- Rotate/disable/client remove revoke codes and tokens (apart from issue 1). Disabled members refused at consent, exchange, refresh and on every request.
- Client secrets: only hashes stored; `HashedSecretAuthenticator` wraps the SDK check correctly for post and basic.
- Identity: one path through `AuthMiddleware`; the concurrent two-member test is real (20 parallel requests, MCP and REST).
- Audit: ids, member names, attempts, status only; the secrets test covers member tokens, client secrets, codes, verifiers, access and refresh tokens across audit file, stdout, stderr and logging.
- Migration: v1 DDL file upgrades in place inside BEGIN IMMEDIATE and keeps members, point, tasks, asks; newer schema refused.
- OAuth off: no routes, plain challenge, fixed tokens unaffected, old access tokens refused.

Notes (not blocking; no change asked in this round):
- Deviation 1 (CSP `form-action` also lists the client's redirect origin, plus `frame-ancestors`/`base-uri`) departs from the frozen C8 header text. The reason is sound (Chromium applies form-action to the redirect after the POST) and the value is built from a strict pattern, so I accept it, but C8 is frozen: it needs a ledger `decision` line. Still unverified in a real browser; T15 should check it.
- Deviations 2–4 (always grant `skein`; basic or post for confidential clients; public_url path must equal base_path) are fine.
- `/authorize` is not rate limited and pending requests are capped at 200 with oldest dropped, so any registered client can evict everyone's in-flight sign-ins with 200 requests (confirmed). Sign-in only, fixed tokens unaffected. A per-client pending cap would close it.
- An owner-added client with no redirect URI yet sends error redirects to any https URL (`/authorize?client_id=cli_…&redirect_uri=https://…&response_type=x` → 302 there with `error=`). It follows from trust on first use and ends at the first approved sign-in; T14's docs should tell owners to pass `--redirect-uri` when they know it.
- A reused (already rotated) refresh token is refused but does not end the grant. OAuth 2.1 suggests it for public clients; C8 does not require it.

## Fix round 2
Changes:
1. src/skein/oauth.py: consent no longer checks the member token in a read transaction of its own. `consent` passes the stripped form token to `_decide(req, token)`. `_decide` resolves it with the new `_member_for_token(db, token)` inside its own write transaction (BEGIN IMMEDIATE), the one that issues the code. The check is the same as `Skein.authenticate`: TOKEN_MAX, `db.get_member_by_token_hash`, enabled, `hashes_match`. A `rotate_token` or disable now commits either before the decision (the token no longer matches, so the attempt counts as a bad token and no code is issued) or after it (`delete_oauth_member` deletes the new code). An empty or oversized token still counts as a failed attempt.
2. tests/test_oauth.py: new `test_member_change_racing_consent_leaves_no_grant`, parametrized over rotate/disable × before/after. It wraps `SkeinOAuth._decide` to commit the member change just before or just after the decision. "before": 400 form, no redirect, one `consent_failed`. "after": the issued code fails at /token. Both cases: no oauth code or token rows for the member, and the old fixed token gets 401. Against the old code, both "before" cases failed with 303, which reproduces the bug.
3. tests/test_oauth.py:789: the vendor redirect is now `com.example.app:/oauth/callback`. No vendor URIs remain in src/ or tests/.

Acceptance `uv run pytest -q`: PASS. `326 passed, 1 warning in 17.95s` (322 before + 4 new; the warning is the existing Starlette httpx/TestClient deprecation).
