## Result
Files changed: src/skein/cli.py, src/skein/mcp_tools.py, src/skein/rest.py, src/skein/auth.py, tests/test_cli.py, tests/test_http.py, tests/test_mcp.py. service.py and store.py untouched.

- `skein serve` always calls `uvicorn.run(..., access_log=False)` (with and without `url_tokens`); test monkeypatches `uvicorn.run` and asserts the kwarg.
- MCP Origin allow-list = http(s) origins derived from the allowed hosts + `config.allowed_origins` (deduplicated, passed through as is, so the SDK's `scheme://host:*` port wildcard also works). Tests: foreign Origin 403 by default, 200 once listed; derived origins still 200; other origins still 403.
- REST bodies over 1 MiB → 413 `{"error":"request body too large","code":"invalid"}`, before parsing: a larger Content-Length is refused unread, and a streamed body is refused once it passes 1 MiB. Exactly 1 MiB is accepted. The 413 is audited (status 413, code invalid). The cap applies where a route reads a body; bodyless routes never read one.
- Audit: an id field is kept only when it fully matches its key's shape (`task_id` = `t_[0-9a-f]{10}`, `ask_id` = `a_[0-9a-f]{10}`, `member` = service `NAME_RE`, `id` = task or ask id); anything else goes to `lens` under the same key as its length. Returned ids get the same check. The 40-char clip is gone (shapes bound the length). Failed-auth `path` is clipped to 200 chars.
- New tests fail on the pre-T09 source (8 failed, the 1 MiB boundary test passes either way) and pass after.

Acceptance: `uv run pytest -q` → `245 passed, 1 warning in 2.69s` (the warning is the existing Starlette TestClient deprecation).

- FastMCP argument-validation failures (missing argument, wrong type such as `limit="abc"`) never reach skein's code: the caller gets an MCP `isError` result with pydantic text instead of `{"error","code":"invalid"}`, and no audit line is written. Left as is per brief; worth one line in the docs.
- Docs could mention: `allowed_origins`, uvicorn access log is always off, the REST 413 response, and that a malformed id in the audit log appears as a length under `lens`.
