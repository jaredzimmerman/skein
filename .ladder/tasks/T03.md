# T03: HTTP app — auth, MCP tools, REST, audit log + tests
Tier: opus · Reviewer: fable · Deps: T01 (service), T02 (config)

## Brief
Goal: the network surface. One Starlette app serving MCP (streamable HTTP) and REST for every member, with per-request identity from the member's token.
Contract: .ladder/PLAN.md §C4 (HTTP surface, quirks, audit log), §C5 (tool names, annotations, instructions), and the service API in §C2 as implemented in src/skein/service.py (read it; do not change it — if it is missing something you need, write the gap in your Result and work around it in the transport only if the rule stays in service).
Files: src/skein/app.py, src/skein/auth.py, src/skein/mcp_tools.py, src/skein/rest.py, tests/test_http.py, tests/test_mcp.py (tests/conftest.py: add fixtures only, don't break existing ones)
Acceptance: `uv run pytest tests/test_http.py tests/test_mcp.py -q`
Constraints:
- `create_app(config, skein=None)`; when skein is None build it from config.db. Mount everything under config.base_path.
- Composing FastMCP into a parent Starlette app: its session manager must run inside the parent app's lifespan (mcp 1.30). Verify, don't assume.
- Identity must reach each tool call per request (middleware → request.state or a contextvar; inside a FastMCP tool, `Context.request_context.request` may expose the Starlette request — verify against the installed mcp 1.30 source in .venv). REQUIRED test: two members with different tokens call `skein_whoami` and `skein_inbox` through the real MCP transport (concurrently, e.g. with anyio/asyncio gather over the mcp streamable HTTP client or JSON-RPC POSTs via httpx ASGI transport) and each gets only its own identity and tasks.
- Tests cover: 401 (no token, wrong token, disabled member, token in query when url_tokens=false), query token accepted when url_tokens=true, healthz without auth, GET SSE → 405, plain GET → help JSON, Host-header rejection for an unlisted host, REST happy path for a full round trip (point assigns → member claims → member submits needs_input → point follows up → member submits done → point inbox shows it finished), REST error code mapping (403/404/400/409), every MCP tool reachable and point-only tools returning {"error","code":"forbidden"} for a member, audit log lines contain lengths and never task text or tokens, base_path="/skein" works.
- Server instructions text built from config.owner and config.answer_time; no hardcoded names or hostnames.
