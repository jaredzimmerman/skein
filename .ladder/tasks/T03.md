## Result
Files: src/skein/{app,auth,mcp_tools,rest}.py, tests/test_http.py, tests/test_mcp.py, tests/conftest.py (added fixtures `team` = lead(point)/alpha/beta → tokens, `audit_path`; existing fixtures untouched).
Acceptance: PASS. `uv run pytest tests/test_http.py tests/test_mcp.py -q` → `60 passed, 1 warning in 4.55s`. Full suite: `178 passed`.

Verified against mcp 1.30 source and by tests:
- Composition: `create_app` calls `mcp.streamable_http_app()` only to create `mcp.session_manager`, serves /mcp through its own ASGI endpoint, and runs `session_manager.run()` in the parent Starlette lifespan. Test proves a /mcp call without the lifespan raises "Task group is not initialized" and works with it.
- Identity: `AuthMiddleware` (pure ASGI) sets `scope["skein.member"]`; tools read it from `ctx.request_context.request` (the Starlette `Request` the transport builds from that scope for each POST). No contextvars or globals. The concurrency test (SDK `ClientSession` for 2 members + 16 interleaved raw POSTs) fails under a deliberately leaky "last authenticated member" mutation (checked from a scratch file, not committed).
- Service calls run in threads (`anyio.to_thread` / `run_in_threadpool`); service.py unchanged; no service gaps found.

Interpretations (contract silent):
- Auth covers everything but `B/healthz`, including GET /mcp help and the SSE-GET 405.
- Host check (421) applies to /mcp only, via mcp's `TransportSecuritySettings`. `allowed_origins` = `http(s)://` + each allowed host, so a request with a foreign `Origin` header gets 403.
- REST success is always 200. Unknown route → 404, wrong method → 405 (with `Allow`), both `{"error","code"}`. A body that isn't a JSON object, or holds lone surrogates → 400 invalid (transport parse check). Over MCP a lone surrogate still reaches the service and comes back `internal`.
- MCP argument names mirror the REST bodies: `skein_note(note)`, `skein_answer(answer)`, `skein_follow_up(text)`, `skein_reassign(member, note)`.
- Annotations: `readOnlyHint` true on the 6 contract tools, false elsewhere; `destructiveHint` true only on cancel; `openWorldHint` false.
- Tool results are structured content plus the same JSON as text. Errors are normal results `{"error","code"}`, not protocol errors.
- Audit lines: `kind` rest|mcp|auth_failed, `member`, `route`/`tool`, `status` (+`code`), `ids` (task_id/ask_id/member/created id, clipped to 40 chars), `lens`. The query string is never logged; failed auth logs method, path, UA (≤200 chars), IP, reason missing|invalid. Unexpected errors go to stderr as type + frames, never the message.

Open issues:
- If a real client sends its own `Origin` header on /mcp it gets 403; add that origin (e.g. a config key) if it happens. Not seen in tests.
- Behind a reverse proxy, the audit IP is the proxy's unless uvicorn trusts its forwarded headers (deploy setting).
- Starlette's TestClient warns that httpx is deprecated in favour of httpx2 (harmless).
